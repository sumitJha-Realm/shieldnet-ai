ShieldNet AI: Customer Solution Brief

Version: April 2026

1. Executive Summary

ShieldNet AI is a real-time malicious URL detection platform that combines deterministic threat analysis, semantic vector retrieval, Atlas text search, and optional Foundry-based agentic reasoning. It helps security teams triage suspicious URLs faster with explainable evidence and campaign-level context.

Important: This environment is a validation/demo implementation. Detection outcomes and campaign links depend on seeded data quality and should be calibrated before production rollout.

2. Business Value

  • Accelerates URL triage with automated risk scoring and explainable evidence.
  • Improves detection quality using both lexical search and semantic similarity.
  • Supports campaign intelligence by clustering related malicious URLs.
  • Enables analyst workflows through searchable threat database and status management.

5. Data Sources and Ingestion

  • Live scan ingestion: Each scan request creates or updates a URL record in urls.
  • Threat intel seeding: Threat feed-style records are stored in urls with docType=threat_intel.
  • Campaign updates: Detected clusters create/update documents in campaigns.
  • Graph edges: Similarity relations are written into url_edges.
  • Operational rules: Active configuration is maintained in scan_rules.

7. Embedding Strategy

  • Embeddings are generated from summaryText (URL + metadata + threat signals), not raw URL alone.
  • Model default: voyage-4, output dimension: 1024, similarity: cosine.
  • Campaign-aware re-embedding updates vectors after campaign tagging to improve future retrieval precision.
  • Unified retrieval: scanner and threat-intel documents share the same embedding field in one collection.

8. Search and Detection Pipeline

  1. Receive URL and perform waterfall retrieval checks (cache/DB).
  2. Extract deterministic threat signals (payload, structure, DGA, homoglyph, etc.).
  3. Build summary text and generate embedding.
  4. Run vector search for semantic neighbors and optional lexical/hybrid retrieval.
  5. Compute weighted risk and classification.
  6. Detect and attach campaign context (if matched).
  7. Persist updated record and return explainable result.

9. Security and Governance Notes

  • No hardcoded secrets should be committed; use environment variables and secret stores.
  • Threat decisions should be calibrated with production data and analyst feedback loops.
  • Use role-based access for scan rules and status override operations.

10. Deployment Summary

  • Local and demo deployment via Docker Compose.
  • Frontend and backend can be split for managed hosting.
  • MongoDB Atlas hosts data/search/vector indexes.
